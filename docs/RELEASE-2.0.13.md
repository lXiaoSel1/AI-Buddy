# AI 酱 2.0.13

2.0.13 集中修复安装、联网和插件中断后的处理，补齐本地安装入口与网络设置，修正语音组件校验误报。30fps 与 60fps 两版功能相同；现有媒体、运行库和大模型组件继续复用。

## 安装、升级和扩展

- 安装器按包记录与实际文件校验复用未变的资源，不再因为升级就把角色、动作和运行库全部下载一遍；缺记录、文件缺失或校验不符的包仍需下载。下载估算会扣除可以复用的包与已校验缓存。
- 完整包增加「安装或更新 AI 酱.cmd」。解压后可直接运行 AI Buddy.exe，也可用这个入口断网安装到新位置或升级已有安装。安装只取清单中的程序文件，不带入来源文件夹的个人存档；所需本地资源缺失或损坏时停止，不转为联网下载。本地来源不显示下载镜像输入。
- 修复扩展服务恢复后第一次进入目录仍未就绪，以及迁移后更新策略未跟随官方来源的问题。不兼容的已装版本显示原因；有兼容新版时提示更新，没有时等待插件更新。
- 修复完整包首次使用设置检查更新时，尚未建立事务目录而报 `APP_UPDATE_FAILED` 的问题；移动目录后继续使用真实安装身份核对。
- 成功回退后，同一条回退记录不能再次使用。回退到 2.0.11 或更早时，安装器先说明语音插件需要重装，角色声音和设置保留。

## 网络设置

- 「通用设置 → 网络」提供「跟随系统」（默认）、「手动」和「不使用」，支持 HTTP/HTTPS 代理；「测试」按当前设置检查扩展目录。扩展中心、受控组件下载、模型列表与聊天、更新和云配音等请求接入这些设置，安装器读取同一份设置。
- GitHub 与 HuggingFace 镜像默认留空，只接受 HTTPS 主机地址。镜像保留原路径及查询参数，文件仍核对大小和 SHA-256，目录及更新仍验签。镜像校验失败时可单次「改用官方地址重试」，不改保存的镜像。
- 大文件下载保留已下载部分，支持下一次续传；连接与无数据等待有超时，下载过程不再因固定总时长中止。连不上、超时、限流、证书或镜像错误给出对应说明，技术码保留在详情中。
- 局域网模型地址支持 HTTP 和不填 Key，保存时提示未加密；支持 10.x、172.16–31.x、192.168.x 与 .local，末尾的 /chat/completions 或 /models 会自动整理。Kimi 和 MiniMax 可以选中国大陆或国际地区，换地区需使用对应 Key。
- 这些设置覆盖 AI 酱接入的请求链，不能保证 NapCat 自身网络、外部命令行工具、Git 或所有第三方请求都跟随；SOCKS 暂不支持。GitHub 限流后的官方更新校验载体已准备支持，需签名并公开相应载体后才能验证正式路径。

## 语音

- 修复读取文件引起通知后，把内容未变误判为校验失败的问题。校验进度按稳定文件保存，中断后可复用仍匹配的记录；启动不再重复整套完整校验。缺文件或哈希不符才引导下载，校验期间变动或中断则提示「重新校验」。
- 语音三包为 1.0.3，需要本体 2.0.13；两个引擎精确依赖共用组件 1.0.3。预制参考录音保持原字节。
- MiniMax 云配音可选中国大陆或国际地区，Key 不通用；请求跟随网络代理设置。只有已确认过期的音色显示「重新克隆…」，继续走原有费用确认，不把未知结果当作过期，也不自动重新收费。

## 陪伴和官方插件

- 每日 CG 改按电脑系统时间的 10:00 和 22:00 执行。群聊 Auto 重启后有未确认请求时显示「上一轮没有完成。」，可明确选择「从下一位继续」或「停止 Auto」，不重发未知结果；近期记录有界，去重证据另存。
- B站陪伴 2.0.16：已确认阅读可跨天继续，额度仍记在开始日；自动新开始仍受日期和时段限制。登录过期时暂停并提示重新扫码，不继续调用模型；平台限制请求单独说明。视频或字幕处理超时保留已完成的材料。
- QQ连接 2.0.10：打开「AI 酱启动时自动恢复这个账号和角色」后，意外断线按退避间隔重连，最多连续尝试 5 次；手动断开、授权撤销或身份变化不自动重连。改善积压时的持久接收、会话顺序与并发；改回复风格不撤销正在生成的回复。退出时监管自己启动的 NapCat，不处理其他实例。
- QQ 仍按原时间窗口接收消息，没有加入网络自动校时。电脑偏慢时可能提示「电脑时间不准，可能收不到消息。」，偏快时可能静默丢弃部分消息；收不到消息时先同步 Windows 时间，不能保证时钟不准时正常收信。
- 一起玩牌 1.1.5 配合本体 2.0.13：角色连接变化时，可「用现在的连接继续」当前手，或「作废这一手」并退回押上的积分，不算输赢。修正德州人数切换后的盲注衔接；牌桌只保留近期聊天，完整聊天单独分页读取。规则、素材和原权限不变。

## 退出失败后的处理

- 部分服务已停止时，可选「退出并重新打开」或「稍后」。前者只重试未完成步骤，成功的保存不重复；后者保持阻止新活动。再次失败会说明没完成的步骤。
- 只有准备、插件关闭及全部保存步骤都确认成功，才提供「仍然重新打开」。保存或最终收尾未确认时不提供强制重开；某些数据库或流的失败会持续保持未确认，需要先处理底层问题。已关闭的业务存储不会假装热恢复，为安装更新而退出也不会走重新打开流程。
