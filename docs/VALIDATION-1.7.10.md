# AI Buddy 1.7.10 — 30fps / 60fps 与历史账本优化

两版使用相同源码、功能和存档格式。30fps 版降低动作视频帧率；60fps 版保留已验收视频及节奏修订。两版均包含 11 位角色、每位 18 套独立动作、完整的 3,225 张鼠标方向图和 80 张表情。方向图和表情采用 WebP Q95，透明通道保持逐像素一致。Q95 颜色为有损压缩，不宣称整张图片无损。

新安装、缺省或非法设置，以及恢复默认时，桌宠大小为 125%；已有有效自定义大小保持不变。此前完成的各角色大小校准和正常状态即时切换继续保留。

## 本地历史与内存

仅实施已批准的两步：释放解析后的大型 JSON 原文，随后将完整请求历史保存在本机 SQLite 中，按游标和分页读取。没有新增全局 LRU / 通知合并，也没有重写任务、好感、升级或 CG 事件规则。

数据库位于现有存档内的 `usage-ledger-v2/`。首次升级验证旧快照及提交边界，分批导入，完整验证后发布。中断时依据已提交边界恢复；旧日志、快照保留。回退前必须停止写入、保存一致数据库，并将升级后用量导出到旧版兼容账本，不能直接删除新数据库丢弃新增记录。

固定历史独立诊断：442,357 条规范化请求、70,203,806,712 Token，新旧快照和查询逐项完全一致。相同运行时强制 GC 后：

| 独立诊断 | 稳定 JS 堆 | 首次恢复 | 首次规范化 | 全历史冷查询 |
| --- | ---: | ---: | ---: | ---: |
| 1.7.9 基线 | 986 MiB | 5.1 秒 | 2.4 秒 | 2.2 秒 |
| 仅第一步 | 531 MiB | 5.3 秒 | 2.4 秒 | 2.2 秒 |
| 第一、二步首次迁移 | 9.1 MiB | 37.6 秒 | 25.8 秒 | 5.1 秒 |
| 第一、二步重新启动 | 8.7 MiB | 3.9 秒 | 复用持久化记录 | 5.4 秒 |

这是隔离数据、强制 GC 的诊断结果，**不是整个应用的生产内存**。产品没有添加定时 GC。SQLite、Electron、GPU、视频解码、会话摘要仍占内存；全历史冷查询比旧内存查询慢，约 5 秒。本轮没有承诺进一步缓存优化。已有导出接口仍返回汇总字符串，导出最终字符串峰值仍存在。

十万请求验证包含八类工具、筛选、分页、项目排序、时区与聚合、费用、导出、用量修正和重启。无变化重复查询不遍历全量历史，也不重复执行会话统计 SQL。源代码回归 272 项通过。

## 媒体检查

198 个 30fps 视频从已批准透明原帧重新编码，保持画布、锚点、完整周期和末帧实际时长；60fps 原视频哈希保持一致。每段核对时间戳、透明通道及首／中／末帧的实际 VP9 解码结果，另检查 11 张角色动作对照图。原素材继续在本地保留，发行包不夹带原始制作序列。

125% 大小下，方向帧保留完整文件和原有清晰度。解码先按实际目标尺寸缩放，再从缓存位图中去除全透明空白，绘制时恢复原位置；没有改变人物比例，也没有增加既有 128 MiB 方向缓存上限。这是默认放大后的媒体兼容修复，不是延期的全局缓存改造。

## 验收范围

30fps 与 60fps 已分别在真实 Electron 中检查全部 198 个动作的实际推进、11 个角色的四档速度与中途变速、暂停恢复，以及三轮角色切换／动作页滚动。退出页面后，预览解码器、帧缓存和待加载项均释放；三轮工作集检查未发现持续增长。检查了 900、1180、1600、1920 宽度和中英文设置布局。

两版均检查默认 125%、已保存大小保留、角色校准、正常状态即时切换、拖动期间的切换等待、点击穿透、完成两轮跳跃与气泡同步。全部角色完成上下左右与每秒两圈的鼠标输入检查；3,225 张方向缓存位图重建结果与原绘制结果逐像素一致。

测试使用独立存档、现有图像、合成日志和模拟服务，不发起付费模型请求；真实绘图成片沿用此前验收，未重新生成。便携包以最终 ZIP 解压结果验证根目录 EXE、中文／空格路径、无外部 Node.js／Python 和单实例；正式入口验收及下载哈希随 Release 记录交付。上述技术验收不替代用户对动画观感的评价。

## 下载与恢复

在同一个 v1.7.10 Release 选择 30fps 或 60fps。两版功能和存档格式相同，不需要同时安装。解压后直接运行根目录 `AI Buddy.exe`，不需要自行安装 Node.js 或 Python。若某个 ZIP 超过 GitHub 单资产限制，会提供分卷和 Windows 合并校验脚本；按 Release 下载说明操作。

最终发行包实测，不含用户存档、数据库和备份：

| 版本 | 解压后 | ZIP | 分发方式 |
| --- | ---: | ---: | --- |
| 30fps | 1,852,465,166 字节（1.73 GiB） | 1,584,661,469 字节（1.48 GiB） | 单个 ZIP |
| 60fps | 2,413,902,122 字节（2.25 GiB） | 2,153,214,554 字节（2.01 GiB） | 三段分卷＋Windows 合并脚本 |

两版最终 ZIP 各 4,043 个清单文件逐项校验，解压后无需外部 Node.js／Python 即可直接启动。60fps 三卷重新合并后与原 ZIP 哈希完全一致。

- 30fps ZIP SHA-256：`6e8fb6ab65acc489cf37b2811f267189a1fc1c6919b7363f2d8417b4584b8004`
- 60fps ZIP SHA-256：`3caa10fd3b62c7290f6824900623484845b87e824eba14ce89beefddf7858544`

发行包不包含开发者存档、API 密钥、日志或数据库。上一正式版保留可校验恢复包；不要复制正在写入的单个 SQLite 文件作为完整备份。

首次大历史统计查询曾超过控制管道原有 30 秒收包超时。现将收包空闲限制和已受理请求执行期限分开，执行期限为 150 秒；增加慢处理、超时回复及空连接错误检查。首轮正式验收自动回退，并验证新增用量兼容导出，之后重新构建验收。

增加完整应用管道验证：同份冻结历史连同 41 条通用来源记录，共 442,398 条请求。冷启动在应用 ready 后等候索引约 46.5 秒，首次统计约 36 秒，同条件重复查询约 62 毫秒。再次启动约 5.7 秒达到可查询状态，全历史首次查询约 6.5 秒；迁移完成记录没有变化，总量逐项相同，确认复用了数据库。这组数据同样是独立样本，不能替代用户机器上的启动实测。

SQLite 是以额外磁盘索引换取较低常驻内存。该完整历史样本的两份数据库合计约 1.70 GiB；保留的旧快照、迁移备份及 WAL 不计入软件发行包大小。软件压缩体积和存档／索引体积分别统计。

## 正式入口验证

原桌面入口已更新为 1.7.10 的 30fps 版，存档目录不变。1.7.9 完整归档通过哈希校验，并从归档恢复启动验证；随后备份最新数据、切换版本、检查单实例及全部设置。正式环境再次启动约 9.9 秒可查询，全历史查询约 10.2 秒；迁移记录保持不变，没有重新导入历史。

正式环境在 Galgame 页面、桌宠工作动作及监控运行时，进程树私有工作集即时读数为 670.4 MiB；没有强制 GC。这不是控制变量性能实验，不能用该读数承诺每台机器的固定节省比例。两份 SQLite 主文件合计约 1.74 GiB，另外约 16.6 MiB 为当时 WAL/共享内存；这些属于用户索引，独立于上表软件大小。
